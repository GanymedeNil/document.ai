# EAER 精简版部署说明

精简版在一台机器上运行 2 个应用进程（接口、后台任务）和 2 个基础组件（PostgreSQL 18.6、OpenSearch 3.9.0），由仓库根目录的 `docker-compose.yml` 一次启动（开发文档 13.1）。集群版把同样的模块拆开部署并替换文件存储与任务队列，另行说明。

验收要求（AC-13-1）：在干净机器上按本说明安装，30 分钟内启动并通过冒烟测试集。

## 1. 准备

| 项目 | 要求 |
| --- | --- |
| 机器 | 64 位 Linux 或 macOS，4 核 8 GB 内存以上，磁盘按文档量估算（见机器规格对照表，AC-13-6 待测）。OpenSearch 默认堆 1 GB |
| 软件 | Docker 24 以上（含 compose v2）；运行冒烟测试的机器另需 Python 3.12 以上（只用标准库） |
| 网络 | 构建镜像时能访问 Docker Hub 与 PyPI；运行时能访问模型服务 |
| 模型服务 | 生成（OpenAI 兼容的 `/chat/completions`）、Embedding（`/embeddings`）、重排（`/rerank`）三项都要有，缺一项接口与后台进程都启动报错（12.1）。Embedding 与重排可以用本仓库的参考实现 `modelserver/`（Qwen3-0.6B），部署在本机或另一台有 GPU 的机器上 |

## 2. 安装

```bash
git clone <仓库地址> eaer && cd eaer
cp deploy/eaer.env.example deploy/eaer.env
cp deploy/tokens.example.json deploy/tokens.json
```

编辑 `deploy/eaer.env`：

- `EAER_DB_PASSWORD`：随机口令（`python3 -c "import secrets; print(secrets.token_urlsafe(18))"`）；
- 模型服务：`EAER_GEN_*`、`EAER_EMBED_*`、`EAER_RERANK_*`。服务在本机时地址写 `http://host.docker.internal:端口/v1`，容器经它访问宿主机；
- 其余保持默认即可：分词 `standard`、准入 `required`、Trace 不导出。

编辑 `deploy/tokens.json`：把三个键换成随机令牌（参考身份实现，客户现场换成 SSO）。`roles` 是接口角色（editor 上传与归档、reviewer 审核），`principals` 是文档权限角色。

两个文件都含密钥，不纳入版本控制（`.gitignore` 已排除），权限设为 600。

启动：

```bash
docker compose --env-file deploy/eaer.env up -d --build
```

启动顺序由编排文件保证：PostgreSQL 就绪 → 迁移（`migrate`，已是最新则不动）→ OpenSearch 就绪 → 建索引（`init-index`，别名已存在则跳过）→ 接口（`api`，端口 `EAER_API_PORT`，默认 8000）与后台任务（`worker`）。PostgreSQL 与 OpenSearch 不对外开放端口。

查看状态：`docker compose --env-file deploy/eaer.env ps`，`api` 为 healthy 即可。

## 3. 冒烟测试

```bash
python3 -m eaer.smoke --api http://localhost:8000 --editor <editor 令牌> --reviewer <reviewer 令牌> --user <user 令牌>
```

九步：上传、等后台解析后审核通过、提问并引用新文档（等写入索引）、证据与会话接口、归档、归档后不再引用、取消归档、取消归档后又能引用、清理（再次归档）。全部通过输出 `"ok": true`、退出码 0。冒烟测试只经对外接口，可在任何能访问接口的机器上运行。

## 4. 准入检查（开发文档 12.3）

`EAER_ADMISSION=required` 时，Verified 与 Deep 只对通过准入检查的生成模型开启；没有准入记录时两者关闭，回答中会说明。部署后对每个租户跑一次：

```bash
docker compose --env-file deploy/eaer.env run --rm -e EAER_ENV=eval worker \
  sh -c 'python -m eaer.evalrun.admission <验证器评测集.xlsx> --admin-url "$EAER_DATABASE_URL" --database-url "$EAER_DATABASE_URL" --tenant t1'
```

（评测集文件需挂载进容器；精简版的数据库账号有建库权限，准入检查在临时库中运行。）

## 5. 日常运维

| 事项 | 命令 |
| --- | --- |
| 日志 | `docker compose --env-file deploy/eaer.env logs -f api worker` |
| 监控指标（13.3） | `docker compose --env-file deploy/eaer.env exec worker python -m eaer.metrics --opensearch http://opensearch:9200`（各模式请求量与 P95、升级与拒答比例、结论分布、入库队列、索引更新延迟、对账差异） |
| Trace（13.3） | `EAER_TRACE_EXPORTER=console` 打印到日志；`otlp` 导出到 Phoenix 等接收端（镜像用 `--build-arg WITH_OTLP=1` 构建，并设 `OTEL_EXPORTER_OTLP_ENDPOINT`）。Trace 不含原文 |
| 旧索引清理 | 重建切换后旧索引保留 24 小时，每天运行一次：`… exec worker python -m eaer.ingestion drop-retired` |
| Trace 清理 | 后台进程每小时自动做；手动：`… exec worker python -m eaer.ingestion purge` |
| 索引对账补写 | 后台进程每小时自动做（`EAER_RECONCILE_SECONDS`）：索引里缺的、多的版本补排索引任务；手动查看 `… exec worker python -m eaer.ingestion reconcile`（有差异时退出码 1），补写加 `--repair` |
| 升级 | 拉取新代码后 `docker compose --env-file deploy/eaer.env up -d --build`，迁移自动执行 |

## 6. 索引重建（开发文档 5.3、AC-13-3）

检索索引可由数据库与原件重建，不需要备份。更换 Embedding 模型或分词器时：

```bash
docker compose --env-file deploy/eaer.env exec worker python -m eaer.ingestion rebuild --build-id b$(date +%Y%m%d%H%M)
docker compose --env-file deploy/eaer.env restart worker api     # 进程启动时核对别名指向的索引
```

重建期间查询不中断（写完再切换别名，AC-5-3）；向量取自数据库中的缓存，不重新调用 Embedding 服务，只有更换 Embedding 模型时才重新计算。

索引丢失（例如 OpenSearch 数据卷损坏）时，删除索引后执行 `ensure-index` 即从数据库重建；`restart worker api` 后恢复。

## 7. 备份与恢复（开发文档 13.4、AC-13-4）

备份（建议每天定时运行）：

```bash
deploy/backup.sh                    # 写到 backups/<时间>/：eaer.dump、files.tgz、manifest.txt、SHA256SUMS
```

恢复到新环境（新的编排项目与数据卷，原环境不受影响）：

```bash
EAER_PROJECT=eaer-restore EAER_API_PORT=8001 deploy/restore.sh backups/<时间>
```

恢复后跑冒烟测试；演练时另做回溯快照比对：

```bash
python3 -m eaer.smoke snapshot --api http://localhost:8000 --user <令牌> --out 恢复前.json
python3 -m eaer.smoke snapshot --api http://localhost:8001 --user <令牌> --out 恢复后.json
python3 -m eaer.smoke diff 恢复前.json 恢复后.json
```

精简版的备份是每日全量（pg_dump），恢复点最多丢失一天的数据。持续归档预写日志（按时间点恢复）只在集群版做（开发文档 13.4，2026-11-14 确定）。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `api` 或 `worker` 反复重启，日志写“配置错误” | 模型服务配置缺项或地址不通；按日志补全 `deploy/eaer.env` 后 `up -d` |
| `init-index` 失败 | Embedding 服务不可用（建索引要知道向量维度）；修好后 `docker compose … up -d` 重新执行 |
| 回答说明“Verified、Deep 未开启” | 没有准入记录，见第 4 节 |
| 刚审核通过的文档查不到 | 索引在后台写入，通常几秒；`python -m eaer.metrics` 查看入库队列与索引更新延迟。`ingest_queue.waiting_retry` 不为 0 是任务失败后在退避（多半是 Embedding 服务过载，30 秒、2 分钟、10 分钟后再试）；用完尝试次数的由每小时的对账补写，等不及可手动 `reconcile --repair`。`index_repair.failed` 不为 0 说明补写后仍写不进去，看 worker 日志与任务的 last_error |
