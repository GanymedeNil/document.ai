## 解读（2026-11-14）

- Adaptive 比传统 Hybrid RAG 多答对 13 条，全部来自需要时间或版本处理的三类：历史时点 0→5、回溯 2→5、版本差异 0→5。传统做法只检索当前生效的内容，问某天的取值、问改了什么时答不出；其余各类两者相同。
- Always-Agent 与 Adaptive 在这三类上相当，但每个问题都走 Deep 与 Verified：耗时中位数约是 Adaptive 的 2 倍、生成 token 多约 35%，正确数还少 3 条（当前生效 4/5、冲突 3/5、历史时点 4/5；原因未逐条核查）。
- 图表类三者都是 0/5，需要视觉模型（AC-14-6）；冲突类三者都在 3–4/5，是已知的改进点（CLAUDE.md）。
- 传统 Hybrid RAG 的 P95 19.7 秒与 Always-Agent 相当，不合常理：它每问只有一次生成。多半是本机模型服务的个别慢调用（部署演练中见过重排首调超时重试），未逐条核查；比较耗时以中位数为准。
- 成本按生成 token 计：乘以所用生成模型的单价即为每问金额；Embedding 与重排为本机自部署，不计费。
- 只有 45 条合成查询，一条之差就是 2 个百分点；结论用于方向判断，产品基线以全量评测与真实语料为准。
