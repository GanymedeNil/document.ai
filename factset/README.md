# factset：EAER 合成评测集事实表工具

对应开发文档第 14.2 节合成流程的第 2–5 步：校验事实表、生成文档、检查文档、计算答案；以及验收项 AC-14-1、AC-14-3 和 AC-14-2 的程序检查部分。

## 用法

1. 在线事实表页面中下载为 .xlsx。
2. 安装依赖：`pip install -r requirements.txt`（Python 3.12 及以上）。
3. 校验并比对人工答案：

   ```
   python -m factset check 事实表.xlsx
   ```

   校验不通过时列出每个问题所在的表和行；校验通过后逐个查询比对，不一致的会列出差异。有问题时退出码为 1，可直接放进 CI。

4. 导出评测集：

   ```
   python -m factset export 事实表.xlsx -o 评测集.jsonl
   ```

   每行一个查询，`expected` 是程序算出的标准答案：是否拒答、依据事实、来源等级、必须出现的取值、是否需标注“未验证”、是否冲突。

5. 按事实表生成文档（每个版本一份）和清单：

   ```
   python -m factset render 事实表.xlsx -o 文档目录            # 默认 Word 格式
   python -m factset render 事实表.xlsx -o 文档目录 --format html
   ```

   需要中文字体（如 Noto Sans CJK）来画图表。

6. 检查文档：

   ```
   python -m factset verify-docs 事实表.xlsx 文档目录
   ```

   模板生成的文档和以后经模型改写的文档都要过这道检查。错误必须修正；提示（同一事实键的旧取值出现在新版本中）供人工抽检时留意。

## 文档生成规则

- 正文类事实写成条款句子，表格类事实汇总成一张表，图表类事实画成柱状图。图表的取值只出现在图片里，正文、图注和替代文字都不写，否则不看图也能答对。
- 生效日写法为“正文写明”的版本，末条写“自某年某月某日起施行”；“仅上传时间”和“无”的规范类版本全文不出现任何完整日期。
- “无”的版本在清单中标记为批量导入（`legacy-import`），系统不得把它的上传时间当作时间依据（开发文档 6.2）。
- 新版本写明“原《标题》（第 N 版）同时废止”；记录类文档写报告日期。

`manifest.json` 按审核通过日排列全部版本，并列出全部事件，评测时据此按历史日期装载文档、审核和执行事件。

## 计算规则

与开发文档第 6–9 节一致：

- 系统认知时间：回溯查询取回溯时间点，其余取提问日。版本在审核通过日起可见，有效期更正自事件发生日起生效。
- 判断有效的日期：填了生效时间点取它，否则取系统认知时间。空的生效日不过滤。
- 旧版本的作废日由取代它的新版本推导：新版本生效日为 explicit 时取该日，否则取新版本审核通过日并记为 inferred。
- 归档状态和可访问角色按提问日判断，回溯查询也不例外。
- 冲突时 explicit 优先；同等可信的候选取值不一致时全部列出，不代为选择。
- 来源等级取生效日与作废日中较弱的一个；规范类结论不是 explicit 时须标注“未验证”。

## 表格约定

按表头文字读取，列的顺序可以调整，多出的列会被忽略。程序依赖的结构化列：

- 事件表：`新生效日`、`新来源等级`（有效期更正），`新可访问角色`（权限变更，多个用分号分隔）。
- 查询表：`目标事实键`。

## 测试

```
python -m pytest -q tests/test_factset.py tests/test_render.py
```

`tests/fixture.py` 中的样例与在线模板一致。48 个测试覆盖：16 个查询全部一致；10 类错误数据均被拒绝；两种格式生成的文档全部通过检查；6 类篡改过的文档均被发现。
